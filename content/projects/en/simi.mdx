## Snapshot

- **Role** — I designed, built, and published the extension.
- **Scope** — English-to-Spanish translation on web pages, in GitHub notebooks, and in PDFs opened in Simi’s viewer.
- **Result** — Version 0.3.0 is available on the Chrome Web Store.

## The problem

Copying a sentence into another tab breaks the flow of reading documentation in English. I wanted to check a passage in Spanish with the source text still in view, then pick up where I left off.

## Key decisions

- **Anchor the bubble to the selection.** The translation appears next to the source as soon as the reader finishes selecting text. Simi needs access to each site where it’s enabled, and the bubble has to track the selection through scrolling and window resizes.
- **Use Chrome’s on-device models.** The selected text stays on the device. In return, translation depends on Chrome’s model availability and the page’s permissions. First-time setup may require a download.
- **Open PDFs in a dedicated viewer.** PDF.js let me bring the same selection interaction to documents. Readers have to open the PDF in Simi, and translation only works when the viewer can open the document and its text is selectable.

## Result

- Readers can use the same selection gesture on a web page, in a GitHub notebook preview, or in the PDF viewer and keep the source passage in view.
- Playwright tests in CI cover selection on web pages and in notebooks, as well as navigation in the PDF viewer.

## What I’d do differently

- I’d automate the first translation in a clean Chrome profile to catch regressions during activation and model download. That check is currently manual.
